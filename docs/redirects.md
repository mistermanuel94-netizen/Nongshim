# Redirects

1,074 rules, all HTTP 301. Generated by `tools/ia.mjs` into `data/redirects.json`
and rendered into host formats by `tools/generate-redirects.mjs`. The full
mapping with a stated reason per rule is `audit/redirect-map.csv`.

## Policy

1. **Preserve** a source path when it is already clean, descriptive and
   indexable. All of `/about/*`, `/sustainability/*`, `/pr/*`, `/investors/*`
   and `/contact/*` keep their paths; only a trailing slash is added.
2. **Replace** a source route when it is query-driven, non-descriptive, or
   exposes no URL at all. Products and recipes fall here — the catalogue had no
   URLs whatsoever.
3. Every replaced URL gets a 301 with a stated reason.
4. **No redirect targets another redirect.** Asserted by the content validator
   and by `tests/content.test.ts`.

## What changed and why

| Group | Rules | Reason |
| --- | ---: | --- |
| `/main/index` → `/` | 1 | The apex served a 338-byte page whose only content was `location.href = "/main/index"`. A JavaScript redirect passes no link equity and shows a crawler an empty document with `<title>Insert title here</title>` |
| Trailing-slash normalisation | 34 | One canonical URL form site-wide |
| Renamed for readability | 5 | `/about/globalNongshim` → `/about/global/`, `/investors/ir/list` → `/investors/ir/`, `/investors/finance/audit_list` → `/investors/audit/`, `/pr/overview` → `/press/`, `/pr/baduk` → `/press/baduk/` |
| Catalogue root | 1 | `/brand/main/index` → `/products/` |
| Category tabs | 4 | `?tabType=instant\|snacks\|beverages\|simple` → four indexable category pages |
| Product fragments | 68 | `/brand/main/container?brandId=X` → `/products/{slug}/` |
| Variant fragments | 140 | `/brand/main/detail?prodCode=N` → `/products/{slug}/#{variant}` |
| Recipe list + pagination | 7 | `/recipe/recipe_list?page=N` → `/recipes/page/N/` |
| Recipe detail | 808 | Every recipe at both of its legacy URL forms |
| Removed / consolidated source routes | 5 | Pages that rendered empty, returned 404, or were a stateful step |

### Why 808 recipe redirects for 101 recipes

The source served every recipe at **two** URLs with no canonical between them:

```
/recipe/recipe_view?recipeId=17               ← from a direct link
/recipe/recipe_view?page=3&recipeId=17        ← from the list page
```

The `page` parameter carried through from whichever list page the visitor
clicked, so a recipe had up to eight distinct indexable URLs. All of them
collapse to one canonical recipe page: 101 recipes × 8 forms = 808 rules.

### Products had no URLs at all

The 68-product catalogue was AJAX-only: cards were `<a href="javascript:void(0)">`
with a click handler that fetched an HTML fragment. There is no legacy product
URL to preserve, because none existed.

The 208 product rules therefore map the **fragment endpoints** rather than
pages. Those URLs do exist in the wild — they appear in browser history,
referrer logs and anything that captured a network request — and they now resolve
to the corresponding page instead of returning a bare HTML fragment.

## Source routes that produce no page

| Source URL | Redirects to | Why |
| --- | --- | --- |
| `/pr/pedia` | `/press/` | Rendered a header and nothing else |
| `/pr/pedia/detail` | `/press/` | Returned an empty document (0 bytes of content) |
| `/contact/inquiry_check` | `/contact/inquiry/` | A stateful lookup step this static site does not have |
| `/investors/ir/view` | `/investors/ir/` | Returned **HTTP 404** on the source while being linked from the list page |
| `/investors/finance/audit_view` | `/investors/audit/` | Same |

These paths are listed in `REMOVED_SECTION_PATHS` (`src/config/routes.mjs`) so
no page on the site can link to them. The SEO audit fails the build if one is
linked.

## Host formats

`npm run redirects` writes:

| File | Host |
| --- | --- |
| `dist/_redirects`, `deploy/_redirects` | Netlify (query conditions on the rule line) |
| `dist/_headers`, `deploy/_headers` | Netlify, Cloudflare Pages |
| `deploy/vercel.json` | Vercel (`has: [{ type: "query" }]`) |
| `deploy/cloudflare-pages_redirects` | Cloudflare Pages |
| `deploy/redirects.htaccess` | Apache (`RewriteCond %{QUERY_STRING}`) |
| `deploy/redirects.nginx.conf` | Nginx (`if ($args = ...)` grouped by path) |
| `deploy/redirects.csv` | Cloudflare Bulk Redirects, or any bulk importer |

### Cloudflare Pages needs extra work

**`_redirects` on Cloudflare Pages ignores the query string.** The 48 path-only
rules work; the 1,026 query-string rules do not. Load `deploy/redirects.csv`
into Cloudflare Bulk Redirects, or handle them in a Worker. The generated
`deploy/cloudflare-pages_redirects` says so in a comment at the point where the
missing rules would have been, so the gap cannot be missed silently.

## After launch

1. Submit `https://eng.nongshim.com/sitemap-index.xml` in Search Console.
2. Watch **Coverage → Page with redirect** rise and then fall as Google
   re-crawls the legacy URLs.
3. Watch **Not found (404)** for anything the map missed. Query-string URLs are
   the ones to check first, since they are the host-configuration-sensitive
   half.
4. Keep the redirects in place permanently. A 301 is only obeyed for as long as
   it is served; removing it re-orphans every inbound link.
5. Re-run `npm run redirects` whenever the catalogue changes — new products and
   recipes generate their own rules automatically.
